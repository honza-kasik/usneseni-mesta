= Parsování usnesení města Litovel
:toc:
:toclevels: 2

Pipeline pro deterministické zpracování usnesení Rady a Zastupitelstva města Litovel.

Cílem je:

- převod PDF do strukturované podoby,
- extrakce struktury usnesení,
- resolvování vzájemných referencí,
- vytvoření fulltextového indexu,
- statický export do Jekyll struktury,
- parsování a propojení rozpočtových opatření,
- maximální reprodukovatelnost a auditovatelnost.

Každá fáze je samostatný skript.
Jedno usnesení = jeden JSON soubor.

== Architektura

Pipeline má šest hlavních fází a tři navazující fáze pro rozpočtová opatření:

[cols="1,3"]
|===
|Phase 1
|Parsování PDF → základní JSON

|Phase 2
|Parsování rozpočtových opatření

|Phase 3
|Strukturální analýza usnesení

|Phase 4
|Resolvování referencí mezi usneseními

|Phase 5
|Vytvoření fulltextového indexu usnesení

|Phase 6
|Statický export webu bez rozpočtových opatření

|Phase 7
|Propojení rozpočtových opatření s usneseními

|Phase 8
|Vytvoření fulltextového indexu rozpočtových opatření

|Phase 9
|Statický export z propojených dat
|===

Fáze 5 a 6 jsou na sobě nezávislé – obě čerpají z výstupu fáze 4. Fáze 7 až 9
lze typicky opakovat bez znovuspuštění parsování rozpočtových opatření ve fázi
2.

== Pipeline skript

Všechny fáze lze spustit najednou pomocí `pipeline.py`.

=== Použití

[source,bash]
----
# Celý pipeline od začátku s daty v tomto repozitáři
python pipeline.py --pdf resources --from-phase 1 --to-phase 9

# Přeskočit parsování a pokračovat od analýzy usnesení
python pipeline.py --pdf pdf_dir/ --from-phase 3

# Spustit pouze parsování RO a analýzu usnesení nad existující fází 1
python pipeline.py --pdf pdf_dir/ --from-phase 2 --to-phase 3

# Vlastní pracovní adresář a výstup
python pipeline.py --pdf pdf_dir/ --workdir moje_data/ --export vystup/

# Naparsovat rozpočtová opatření a propojit je s existujícími usneseními z Phase 4
python pipeline.py --from-phase 2 --to-phase 7

# Přegenerovat pouze návazné kroky nad existujícími RO JSON daty
python pipeline.py --from-phase 7 --to-phase 9

# Vlastní adresář s PDF rozpočtových opatření
python pipeline.py --from-phase 2 --to-phase 9 --ro-pdf resources/rozpoctova-opatreni

# Zobrazit příkazy bez spuštění
python pipeline.py --pdf pdf_dir/ --dry-run
----

=== Adresářová struktura

[source]
----
pdf_dir/          ← vstupní PDF soubory (rekurzivně prohledáváno)
work/phase1/      ← výstup fáze 1
work/phase3/      ← výstup fáze 3
work/phase4/      ← výstup fáze 4
work/rozpoctova-opatreni/        ← výstup fáze 2
work/rozpoctova-opatreni-linked/ ← výstup fáze 7
export/assets/usneseni/    ← výstup fáze 5
export/assets/usneseni/ro/ ← výstup fáze 8
export/           ← výstup fáze 6 nebo 9
----

=== Parametry

[cols="1,3"]
|===
|`--pdf DIR`
|Adresář se vstupními PDF usnesení. Prohledává se rekurzivně. Povinný jen při
spuštění fáze 1. Pokud adresář obsahuje i `--ro-pdf`, rozpočtová opatření se
při parsování usnesení přeskočí.

|`--ro-pdf DIR`
|Adresář se vstupními PDF rozpočtových opatření (výchozí:
`resources/rozpoctova-opatreni`)

|`--workdir DIR`
|Pracovní adresář pro meziproduktová data (výchozí: `work/`)

|`--export DIR`
|Cílový adresář statického exportu (výchozí: `export/`)

|`--from-phase N`
|Začít od fáze N (výchozí: 1)

|`--to-phase N`
|Skončit po fázi N (výchozí: 6; fáze 7–9 doplňují rozpočtová opatření)

|`--dry-run`
|Pouze zobrazí příkazy, nespustí je
|===

== Phase 1 – Parsování PDF

Parsování PDF s usneseními Rady nebo Zastupitelstva města Litovel.

=== Vstup

- jeden PDF soubor
- NEBO složka s PDF soubory (při spuštění přes `pipeline.py` se prohledávají i podsložky rekurzivně)

=== Výstup

- jeden JSON soubor = jedno usnesení

=== Použití

[source,bash]
----
python phase1_parse_pdf.py input.pdf output_dir/
python phase1_parse_pdf.py pdf_dir/ output_dir/
----

== Phase 2 – Parsování rozpočtových opatření

Rozpočtová opatření jsou samostatný typ PDF dokumentů, proto se neparsují přes
Phase 1 určenou pro usnesení. Parser vytváří jeden JSON soubor pro každé
opatření.

=== Výstupní struktura

[source,json]
----
{
  "id": "RO/1/2026",
  "number": 1,
  "year": 2026,
  "approval_date": "2025-12-11",
  "approved_by": "Zastupitelstvem města Litovel",
  "organ": "ZM",
  "meeting": {
    "number": 23,
    "type": "zasedání",
    "date": "2025-12-11"
  },
  "source_resolutions": [
    "ZM/6/23/2025"
  ],
  "budget_change_ids": [
    "1/2026/ZM"
  ],
  "sections": [
    {
      "type": "vydaje",
      "label": "Změny ve výdajích",
      "rows": [
        {
          "budget_change_id": "1/2026/ZM",
          "raw_codes": ["3429", "5901", "4 000 000"],
          "amount": "-370 000,00",
          "amount_value": -370000.0,
          "description": "transfery, dary, příspěvky dle rozhodnutí ZML a RML (RZ 1/2026/ZM)"
        }
      ]
    }
  ],
  "notes": [],
  "source_pdf": "resources/rozpoctova-opatreni/...",
  "text_raw": "..."
}
----

=== Použití

[source,bash]
----
python parse_rozpoctova_opatreni.py resources/rozpoctova-opatreni work/rozpoctova-opatreni
----

== Phase 3 – Analýza syrového textu usnesení

Zpracuje JSON z Phase 1.

=== Vstupní struktura

[source,json]
----
{
  "id": "RM/1/1/2022",
  "datum": "2022-10-27",
  "organ": "Rada města Litovel",
  "text_raw": "text_usneseni"
}
----

=== Výstupní struktura

[source,json]
----
{
  "id": "RM/1/1/2022",
  "datum": "2022-10-27",
  "organ": "Rada města Litovel",
  "actions": [
    "schvaluje",
    "souhlasí"
  ],
  "subject": null,
  "items": [
    {
      "label": "a",
      "text": "text_1"
    },
    {
      "label": "b",
      "text": "text_2"
    }
  ],
  "tail": null,
  "references_out": [],
  "amounts": [
    "10.000 Kč"
  ]
}
----

=== Co fáze dělá

- extrahuje akce (např. „schvaluje", „bere na vědomí"),
- rozděluje vícepoložková usnesení na jednotlivé body,
- odděluje `subject` (text před body) a `tail` (text za body),
- extrahuje peněžní částky,
- hrubě extrahuje reference (bez resolvování).

=== Použití

[source,bash]
----
python phase2_resolution_analysis.py --input phase1_dir/ --output phase3_dir/
----

== Phase 4 – Resolvování referencí

Usnesení mohou odkazovat jedno na druhé.
V této fázi se resolvují reference:

- implicitní +
  např. `1853/60` → `RM/1853/60/2025`
- explicitní +
  např. `RM/1853/60/2025`

Resolvované reference:

- jsou doplněny do nového klíče `references_in`,
- vztah je oboustranný.

Na závěr jsou vypsány statistiky do konzole.

=== Vstup

- adresář s JSON soubory ze Phase 3

=== Výstup

- `usneseni.json` – seznam všech usnesení s rozřešenými referencemi
- `refs_index.json` – index rozřešených referencí
- `stats_refs.json` – statistiky resolvování

=== Použití

[source,bash]
----
python phase3_resolve_references.py --input phase3_dir/ --output phase4_dir/
----

== Phase 5 – Vytvoření indexu usnesení

Vytvoří index pro fulltextové vyhledávání.

=== Vstup

- `usneseni.json` ze Phase 4

=== Výstupní struktura

- `index/` – jeden JSON soubor = jeden rok (fulltextový index)
- `data/` – jeden JSON soubor = jeden rok (usnesení)
- `meta.json` – statistická metadata (např. počty rozhodnutí za roky)

=== Použití

[source,bash]
----
python phase4_index_build.py --input phase4_dir/usneseni.json --output export/assets/usneseni/
----

== Phase 6 – Statický export bez rozpočtových opatření

Generuje statické stránky ve struktuře vhodné pro Jekyll.

Vytváří:

- jednotlivé stránky usnesení,
- roční indexy,
- `sitemap-usneseni.xml` pro generované stránky usnesení.

Negeneruje hlavní stránku `/usneseni/` (ta existuje ručně). Nepřepisuje hlavní `sitemap.xml`; sitemap index má vlastnit web nebo projekt, který statický export publikuje.

=== Vstup

- `usneseni.json` ze Phase 4 (stejný vstup jako Phase 5)

=== Výstupní struktura

[source]
----
export/
  usneseni/
    {rok}/
      {slug}/
        index.html   ← stránka jednotlivého usnesení
      index.html     ← roční přehled
  sitemap-usneseni.xml
----

=== Použití

[source,bash]
----
python phase5_static_export.py --input phase4_dir/usneseni.json --output export_dir/
----

Název sitemap souboru lze změnit volbou `--sitemap-filename`, výchozí hodnota je `sitemap-usneseni.xml`.

== Phase 7 – Propojení rozpočtových opatření s usneseními

Po parsování lze vytvořit odvozenou datovou vrstvu, která propojí:

- rozpočtové opatření se schvalujícími usneseními uvedenými v záhlaví PDF,
- usnesení s konkrétními rozpočtovými změnami `RZ`, pokud jsou v textu usnesení
  uvedeny přímo nebo rozsahem.

[source,bash]
----
python crosslink_rozpoctova_opatreni.py \
  --resolutions work/phase4/usneseni.json \
  --opatreni work/rozpoctova-opatreni \
  --output work/rozpoctova-opatreni-linked
----

Výstup:

- `usneseni.json` – kopie usnesení doplněná o vazby na rozpočtová opatření,
- `rozpoctova-opatreni/` – kopie rozpočtových opatření doplněná o vazby na usnesení,
- `budget_change_index.json` – index rozpočtových změn podle `RZ`,
- `stats.json` – statistiky a případné opravy zjevných překlepů v odkazech.

Statický export lze následně vygenerovat z propojených dat spuštěním pipeline do
fáze 9:

[source,bash]
----
python pipeline.py --from-phase 7 --to-phase 9
----

Stránky usnesení pak obsahují také sekci `Rozpočtová opatření`, pokud má dané
usnesení vazbu na konkrétní `RO` nebo `RZ`. Fáze 9 zároveň generuje samostatné
statické stránky rozpočtových opatření:

[source]
----
export/
  rozpoctova-opatreni/
    index.html
    RO-6-2026/
      index.html
----

Rozpočtové změny (`RZ`) jsou odkazy na kotvy uvnitř stránky příslušného
rozpočtového opatření, např.:

[source]
----
/rozpoctova-opatreni/RO-6-2026/#rz-53-2026-rm
----

== Phase 8 – Vytvoření indexu rozpočtových opatření

Vytvoří fulltextový index rozpočtových opatření pro frontendové vyhledávání.
Index se generuje z propojených RO JSON dat a ukládá se přímo do exportní
struktury webu.

=== Vstup

- adresář `work/rozpoctova-opatreni-linked/rozpoctova-opatreni`

=== Výstupní struktura

- `export/assets/usneseni/ro/index/` – fulltextový index po rocích
- `export/assets/usneseni/ro/data/` – RO data po rocích
- `export/assets/usneseni/ro/meta.json` – metadata indexu

=== Použití

[source,bash]
----
python phase4_ro_index_build.py \
  --input work/rozpoctova-opatreni-linked/rozpoctova-opatreni \
  --output export/assets/usneseni/ro
----

== Phase 9 – Statický export včetně rozpočtových opatření

Přegeneruje statický web nad propojenými daty tak, aby stránky usnesení
obsahovaly vazby na `RO` a současně vznikly samostatné stránky rozpočtových
opatření.

Na stránkách rozpočtových opatření se u jednotlivých `RZ` zobrazuje plný text
poznámky z PDF, pokud je k dané změně k dispozici. Účetní řádky zůstávají
zobrazené pod tímto vysvětlením.

=== Vstup

- `work/rozpoctova-opatreni-linked/usneseni.json`
- `work/rozpoctova-opatreni-linked/rozpoctova-opatreni/`

=== Použití

[source,bash]
----
python phase5_static_export.py \
  --input work/rozpoctova-opatreni-linked/usneseni.json \
  --opatreni work/rozpoctova-opatreni-linked/rozpoctova-opatreni \
  --output export
----

== Principy návrhu

- Jedno usnesení = jeden JSON soubor.
- Žádná interpretace obsahu.
- Deterministické zpracování.
- Každá fáze je spustitelná samostatně.
- Vše je rekonstruovatelné z původních PDF.

== Poznámky

Pipeline je navržena pro dlouhodobou udržitelnost a auditovatelnost.
Nevykonává právní interpretaci ani hodnotící analýzu obsahu.
